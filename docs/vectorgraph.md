# VectorGraph in Vector Code

Open Explorer and expand **Work**. Choose **Sign in to VectorGraph** to approve Vector Code in your browser. Choose the workspaces you want the IDE to access, then return to the IDE. No CLI installation or terminal login is required.

Vector Code stores its workspace credentials using the operating system encryption service. These credentials belong to the IDE; **Sign Out** clears them without changing VectorGraph CLI profiles. **Reconnect** starts a new browser approval to renew access or change the authorized workspace selection. Canceling approval preserves the existing signed-in account.

When a local project has no saved association, Work reads the Git origin remote and looks for an enabled repository/team mapping in the authorized VectorGraph workspaces. Equivalent GitHub HTTPS and SSH remotes match. One complete workspace/team match connects automatically. Repository mappings currently do not include a VectorGraph project: Choose Project establishes that additional association explicitly and remembers it per repository; directory names are never used to guess. Missing mappings, multiple matches, non-GitHub repositories, unavailable mapping access, or ambiguous remotes require **Choose Workspace**. The chosen workspace and team are remembered for that project; a saved association never silently falls back to a different authorized workspace.

Work shares Explorer with project navigation and files. Each repository can retain an explicit VectorGraph project association. Work defaults to that linked project, with an assignee filter and an explicit Whole team option. Tickets open in Work Details beside the code; Open in Editor Tab uses the same details component in a normal editor tab. Arrow keys, Home, and End navigate the issue list. Account changes clear stale issue content and invalidate pending requests. New Ticket creates an issue in the linked project. Edit Ticket changes title, description, status, priority and assignee; Post Comment adds activity. Drafts persist locally across navigation and failed requests. Writes use stable idempotency keys for unchanged retries, and a first save detects a changed remote timestamp before updating. The API does not provide an atomic conditional update, so simultaneous edits after that check still follow the server's update semantics.

## Implementation contract

The main process uses the supported device flow at `/cli/v1/auth/device` and `/cli/v1/auth/device/token`, then the CLI operation gateway at `/cli/v1/workspaces/{workspaceId}/operations/{operationId}`. These are the same protocol endpoints used by the official CLI. The IDE only exposes named authentication methods and explicit workspace, team, project, repository and ticket operations over IPC. Ticket writes carry validated fields and idempotency keys; arbitrary operation names remain unavailable. Device codes, access tokens, raw API responses, arbitrary HTTP requests and process execution are not renderer capabilities.

`VectorGraphAuth` owns authorization generations, bounded polling, encrypted persistence and request isolation. `VectorGraphMainService` owns API projections and local repository discovery. The Work view owns project association and interaction, reusing the existing workbench project state, storage, quick picker and issue editor. Repository discovery checks authoritative enabled GitHub mappings and never infers an association from directory names or project documentation.

## Active development work

Selecting a ticket does not make it active. Start Work records the active ticket for this local project. Its details show the current branch and working-tree changes; Open Changes opens native Source Control. Use Current Branch associates the current branch locally. Create Ticket Branch creates and switches to a new branch only when the working tree is clean and its HEAD still matches the reviewed state. It does not overwrite branches, stash, commit, or push. Creating a branch requires a trusted local workspace.

Link Pull Request accepts a GitHub PR from the current repository and records it on the VectorGraph ticket. Branch association is stored in the IDE; pushing a branch and creating the PR remain explicit Source Control/GitHub actions. Existing linked work appears with the ticket. Switching repositories clears the details selection and restores that repository's active ticket, while drafts are retained by workspace and ticket identity.

Project listing requires `planning:read`; ticket creation/updates/links require `issue:write`, and comments require `comment:write`. An older read-only authorization can still read tickets; reconnect with the required grants to use the new operations. Local source and regression checks do not establish live write access.

Repository actions are authorized in the main process against the calling window's open folders, including multi-root workspaces. Paths are canonicalized before comparison, and branch creation checks stored workspace trust (including the saved workspace file) and explicitly uses the reviewed starting commit. After reviewing a conflicting remote edit, Apply Draft to Reviewed Version preserves the draft fields while updating its comparison baseline.
